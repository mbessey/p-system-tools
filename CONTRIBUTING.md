
# Contribution guidelines for p-system-tools
## General Guidelines
The purpose of this project is to preserve UCSD p-System knowledge for the next 50 years. Pull requests are greatly encouraged, whether to fix bugs, add new features, or clarify the documentation, examples, or other non-code resources.

Don't violate anybody's copyrights. It may be "obvious" that any software written for UCSD Pascal is out of Copyright protection by now, but laws vary by jurisdiction, and I am not a Copyright lawyer. Don't contribute code or documentation that is, or is directly derived from, a copyrighted work.

# Ways To Contribute

## Create Issues
If you use the programs, and find problems or have a feature request, file an issue. I have mostly been working without issues as I got things started up, but it's always nice to know what people want to see next.

## Code Contributions
* Code in this repository should strive for simplicity and clarity of explanation first and foremost.
* Since the code will be running on systems ~1000 times faster than the state of the art in the early 1980's, don't fret about micro-optimizations.
* Try to keep a leash on the tendency to address unrelated issues in the same pull request
* Please file an Issue on the project before you start working on something, so that I know you're working on it.

## Documentation
There really isn't much documentation yet. I don't think a documentation website is really necessary. For now, I will likely put everything on the project's Wiki page.

## Archeology
I have not had the time to do an extensive search of the Internet Archive for UCSD Pascal resources, so if you're inclined, pointers to those documents not already mentioned on the Wiki would be great.

## AI Coding assistants and LLM-generated code
The use of AI coding assistants is *explicitly allowed* in this project. Right now, there is only one person reviewing pull requests, so have mercy on me - I will have to read anything you submit.

I ask that you conform to the following guidelines:
* Keep AI-generated code short. Do not make submissions that modify dozens of files deeply - they'll likely be rejected.
* Don't submit any code that you can't adequately explain if I have questions. A blob of code with no human owner does not meet the first guideline at the top of this document.
